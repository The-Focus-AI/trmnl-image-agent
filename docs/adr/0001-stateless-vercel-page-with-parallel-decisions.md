# Stateless Vercel HTML Endpoint Backed by Parallel Decisions and CDN SWR

We replaced the hourly `hermes` → AI image → `git push` → GitHub Pages pipeline (which bloated `.git` past 2.4 GB) with a stateless Vercel endpoint pointed to directly by TRMNL's Screenshot plugin, warmed via Vercel Cron and `Cache-Control: stale-while-revalidate` so responses stay well inside TRMNL's 5-second screenshot timeout without introducing a database. For data ingestion and editorial triage, we use NWS JSON alongside Parallel's `/v1/extract`, `/v1/search`, and live-web-grounded `/v1/decisions` APIs (paired with Gemini for synthesis) rather than static repo calendars or multi-vendor scrapers, giving us calibrated seasonal/status verification against live web evidence with only two API keys (`PARALLEL_API_KEY` and `GEMINI_API_KEY`).
